# 蜡笔小新全站 UI 重绘设计

日期：2026-08-23

## 目标

将当前工作台及其余功能页面统一为一套完整的蜡笔小新主题 UI，同时保留现有业务功能、页面路由、数据读写、AI 助手能力和响应式行为。

本次改造不以“往页面继续贴图”为目标，而是建立角色、场景和控件状态之间的固定关系。人物只出现在页头、空状态、成功或错误反馈等大区域；搜索、筛选、表单、列表和数据格保持清晰、克制。

## 范围

包含以下页面和全局区域：

- 全局顶部栏与侧栏
- 工作台 `/workspace`
- 今日待办 `/todos`
- AI 助手 `/assistant`
- 日历 `/calendar`
- 笔记 `/notes` 及笔记详情页
- 腾讯文档 `/documents`
- 设置 `/settings`

不删除或弱化以下功能：

- 笔记和文档的独立路由、导航入口、组件、API 与数据
- 待办、日历、AI 助手、账号和设置的现有交互
- 移动端导航、加载、错误、空状态和暗色主题能力
- Harness 高级模式及原生助手的数据和会话逻辑

## 视觉原则

### 1. 素材必须有明确边界

- 产品 UI 只使用透明背景角色 PNG、透明场景条或明确放在插画框内的场景图。
- 不直接使用带米色背景、剧情背景或硬矩形边缘的抠图。
- 不使用剧情截图作为最终控件素材。截图只用于动作和构图参考。
- 角色边缘不得通过白色描边模拟透明；透明通道必须真实存在。

### 2. 人物承担状态语义

- 单个人物用于小范围功能身份或状态。
- 合照只用于页头横幅、大型空状态和完成庆祝。
- 同一人物在同一页面只承担一个主要语义，避免重复出现。
- 普通列表行、表单字段和设置项不放人物，保证扫描效率。

### 3. 页面保持产品感

- 保留现有紧凑信息密度和工作型布局。
- 卡片圆角不超过 8px。
- 使用红、黄、绿、蓝作为功能色，避免整页单一色调。
- 固定角色容器尺寸，异步数据和文字变化不得导致布局跳动。
- 桌面和移动端都不得出现文字遮挡、图片压住按钮或横向溢出。

在同目录维护 `SOURCES.md`，记录每个素材的原始页面、获取日期、原始尺寸和项目内文件名。正式页面不直接引用远程地址。

现有可继续使用的透明场景：

- `assistant-toys-clean.png`
- `calendar-school-clean.png`
- 清理后确认透明边缘合格的其他现有素材

不继续使用当前顶部栏的 `shinchan-head-clean.png`。该文件底部角落包含不透明像素，会产生明显方形抠图感。

新增 `CrayonCharacter` 组件，统一处理：

- 素材路径
- 原始宽高比
- `object-fit`
- 裁切方式
- 固定容器尺寸
- 装饰图与语义图的无障碍属性

新增 `CrayonCharacterGroup` 组件，通过透明人物组合生成野原一家和春日部防卫队合照。合照不预先压成带背景的大图，以便在不同页面和断点调整人物间距。

保留 `CrayonDecoration` 作为长条场景和兼容入口，但逐步移除会产生硬边或低清晰度的旧场景。

## 全局区域

### 顶部栏

- 使用透明的小新全身素材，从顶部栏底边自然探出。
- 角色底部裁切隐藏在栏线后，不再显示方形背景。
- 日期、天气、搜索和通知保持原有信息层级。

### 侧栏

- 底部使用小新与小白的透明组合。
- 不再使用覆盖整段侧栏的大型纵向拼贴图。
- 导航项、选中态和退出登录区域保持稳定，不因图片缩放发生位移。

## 页面角色分配

### 工作台

- 今日待办概览：美伢
- 日程安排概览：风间
- 专注时间概览：广志
- 今日待办空状态：春日部防卫队合照
- AI 助手：动感超人；离线或失败状态使用肥嘟嘟左卫门
- 本周日历：野原一家合照
- 侧栏和轻量陪伴：小新与小白

工作台继续保留三个概览卡、今日待办、AI 助手和本周日历。此前隐藏的首页快速笔记和最近文档不恢复，但其独立功能继续保留。

### 今日待办

- 页头角色：美伢
- 空状态与完成庆祝：春日部防卫队
- 逾期状态：美伢的强调状态
- 搜索、状态、优先级和时间筛选保持现有结构

### AI 助手

- 默认欢迎与执行成功：动感超人
- 连接失败、离线、重试和额度类错误：肥嘟嘟左卫门
- 对话列表、消息、建议动作和输入区不放重复人物
- Harness 模式和原生助手使用同一套视觉状态，但不改变连接和会话逻辑

### 日历

- 页头角色：吉永老师
- 节日、周末和新事件点缀：小葵
- 月份标题场景：幼儿园透明长条
- 日期单元格只显示日期、节日和事件信息，不放人物

### 笔记

- 页头角色：正男
- 无笔记、无搜索结果或思考状态：阿呆
- 笔记列表和详情编辑区不放人物
- 置顶、标签、更新日期和删除功能保持现有行为

### 腾讯文档

- 页头角色：梦冴
- 空状态：透明的探索小新
- 腾讯文档连接状态继续使用明确文字和状态标记，不用人物代替
- 链接搜索、刷新、添加、打开和删除行为不变

### 设置

- 页头角色：园长先生
- 外观、能力状态和账号卡片保持安静、紧凑
- 人物不进入每一项设置，也不遮挡选择器或状态文字

## 组件和样式边界

建议新增：

```text
src/components/common/crayon-character.tsx
src/components/common/crayon-character-group.tsx
src/components/common/crayon-page-identity.tsx
```

- `CrayonCharacter`：单个透明人物。
- `CrayonCharacterGroup`：可响应式调整的透明人物合照。
- `CrayonPageIdentity`：页面标题区的人物与标题排布。

页面业务组件继续拥有自己的数据、事件和状态。主题组件不得读取业务 store，不得负责请求或修改数据。

全局主题样式继续放在 `src/app/globals.css` 的蜡笔主题区域。页面特定定位优先通过组件属性和局部类完成，避免依赖复杂的全局后代选择器。

## 响应式规则

- 桌面端页头人物容器宽度固定，标题区域可收缩。
- 中等宽度下缩小或隐藏次要人物，不缩小主要文字。
- 移动端合照改为两行或只保留主要人物。
- 月历格、任务列表、文档网格和设置项优先保证操作区域，不为装饰图片让出关键空间。
- 所有图片使用明确宽高或 `aspect-ratio`，避免加载时布局跳动。

## 暗色主题

- 透明人物继续使用原始颜色。
- 卡片和纸张纹理由主题变量控制，不在图片中烘焙浅色背景。
- 人物阴影只使用低透明度中性色，不能形成白边贴纸效果。
- 功能色在暗色背景下保持可读对比度。

## 测试和验收

### 自动化测试

- 为人物资产注册表添加路径、尺寸和角色键测试。
- 为 `CrayonCharacterGroup` 添加人物顺序和无障碍属性测试。
- 更新工作台布局测试，验证美伢、风间、广志、防卫队、动感超人和野原一家映射。
- 为待办、日历、笔记、文档和设置页面添加身份角色存在性测试。
- 保留并运行现有业务测试，确保主题改造未删除页面功能。

### 静态验证

- `npm test`
- `npm run typecheck`
- 清理 `.next` 后运行 `npm run build`
- `git diff --check`

### 浏览器验证

桌面端和移动端逐页验证：

- 无矩形抠图底色和硬边
- 无图片遮挡标题、按钮、输入框或列表
- 无横向溢出
- 人物容器不随内容变化跳动
- 空状态、有数据状态、错误状态和暗色主题可读
- 浏览器控制台无错误和警告

浏览器通过不代表业务运行时验收。涉及 AI 助手连接、待办增删、日历编辑、笔记保存和文档打开的功能，仍需分别执行现有交互验证。

## 实施顺序

1. 导入并验证透明人物素材。
2. 建立人物注册表、单人组件、合照组件和页面身份组件。
3. 更新顶部栏与侧栏，消除现有方形抠图问题。
4. 更新工作台。
5. 按待办、日历、笔记、文档、设置顺序更新普通页面。
6. 更新 AI 助手欢迎、成功和错误状态。
7. 完成自动化测试、构建、桌面与移动端浏览器验证。

## 完成边界

只有满足以下条件，才能称为完成：

- 素材已进入正式项目目录并由组件引用
- 相关页面代码已实施
- 自动化测试、类型检查和生产构建通过
- 桌面与移动端逐页浏览器验证通过
- 关键业务交互没有因主题改造退化

仅有设计预览、静态 HTML、素材下载或单页截图不算正式实现完成。
